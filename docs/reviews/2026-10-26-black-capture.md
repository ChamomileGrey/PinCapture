| 항목 | 내용 |

| 원인 | 정부24 전자문서 뷰어(`ezPDFReader 2.0G`)와 함께 설치된 화면 캡처 방지 모듈 Teruten WebCube |

## 1. 증상

- 영역 지정(`Ctrl+Alt+A`)을 누르면 모든 모니터가 검은 화면으로 덮여 화면이 꺼진 것처럼 보였습니다(정지 화면 자체가 검정).
- 캡처 결과가 픽셀 하나 남김없이 `#000000`인 이미지로 저장되고 클립보드에도 복사됐습니다.
- 핀캡처를 다시 실행해도 그대로였습니다.
- 오류 메시지나 로그 기록은 없었습니다. 0.6.0은 검은 이미지를 정상 캡처로 처리했습니다.

## 3. 근본 원인

정부24 전자문서 뷰어를 설치할 때 화면 캡처 방지 솔루션 Teruten WebCube가 함께 설치됐습니다. 구조는 다음과 같습니다.

| 구성 요소 | 역할 | 위치·버전 |
|---|---|---|
| `TUCtlSystem` 서비스 | 자동 시작, 주입기를 띄움 | `C:\Windows\SysWOW64\TUCTLSystem.exe` (Teruten.inc, 2.0.1.5) |
| `TDepend` / `TDepend64` | 실행 중인 32비트·64비트 프로세스에 DLL 주입 | `TDepend.exe` 3.0.8.3 |
| `T_Prevent.dll` / `T_Prevent64.dll` | 주입된 프로세스 안에서 화면 캡처 결과를 검게 만듦 | `C:\Windows\SysWOW64\`, `T_Prevent.dll` 3.0.8.6 |

보호된 뷰어가 열려 있는 동안에는 주입된 프로세스의 GDI 화면 캡처가 모두 완전한 검정으로 나옵니다. 핀캡처는 화면을 `QScreen.grabWindow(0)`(GDI)로 찍기 때문에 영향을 받았습니다. 창 캡처(`PrintWindow`)도 같은 이유로 검게 나올 수 있어 0.6.1에서 함께 처리했습니다.

차단이 **캡처하는 쪽 프로세스 안에서** 일어난다고 판단한 근거는 아래와 같습니다(내부 동작은 공개 자료가 없어 추정입니다).

- 같은 새 프로세스가 주입 전 약 3초 동안은 정상으로 찍고, 주입된 뒤 검게 찍었습니다.
- 화면 전체가 `#000000`이었습니다. 보호 창만 가리는 Windows 표준 방식(`SetWindowDisplayAffinity`)이었다면 그 창 부분만 검거나 빠지고 나머지 화면은 정상으로 찍힙니다.

## 5. 영향

| 대상 | 영향 |
|---|---|
| 핀캡처 0.6.0 이하 | 영역 지정 시 모니터 전체를 검은 정지 화면으로 덮음. 검은 이미지 저장·클립보드 복사·보관함 기록. 원인 안내 없음 |
| 다른 캡처 프로그램 | Windows 캡처 도구에도 같은 DLL이 주입돼 있었음. GDI로 화면을 읽는 캡처 프로그램은 똑같이 검게 찍힐 수 있음 → 핀캡처만 바꿔서 해결되는 문제가 아님 |
| 시스템 전체 | 캡처와 무관한 프로그램까지 약 300개 프로세스에 주입됨. 안정성 영향은 확인하지 않음 |
| 개발 환경 | `pytest` 프로세스에 주입되면 faulthandler가 `Windows fatal exception: access violation`을 한 번 출력할 수 있음. 테스트 결과와는 무관. 이와 별도로, offscreen 클립보드에 남은 `QMimeData` 때문에 통과 뒤 `0xC0000005`로 끝나는 경우는 `tests/conftest.py`가 클립보드를 비우고 `os._exit`로 막음. 그 종료는 WebCube와 무관 |

## 6. 왜 재시작이 안 통하는가

- 차단은 핀캡처 안의 상태가 아니라, 주입기가 프로세스마다 넣는 DLL에서 옵니다.
- 새로 띄운 핀캡처도 몇 초 안에 주입됩니다(약 3초 정상 → 검정). 10:04:05 재실행 뒤 10:04:43 캡처가 검었던 것이 그 예입니다.
- 주입기를 띄우는 `TUCtlSystem`은 자동 시작 서비스라 핀캡처를 몇 번 다시 실행해도 그대로 있습니다.
- 그래서 0.6.1 안내 창에는 "다시 시작" 버튼을 일부러 두지 않았습니다(`tests/test_capture_blocked.py`의 `test_explanation_points_to_the_viewer_not_a_restart`).
- PC를 다시 시작해도 서비스는 다시 뜹니다. 재부팅이 효과가 있다면 뷰어가 닫힌 상태로 시작하기 때문으로 보이며, 아직 검증하지 않았습니다(9절 과제 3).

## 7. 해결·우회 (사용자 안내)

1. 열려 있는 전자문서 보기 창(예: 정부24 '전자문서 전용 Viewer')을 닫고 다시 캡처합니다.
2. 그래도 검으면 그 사이트의 브라우저 창도 닫습니다.
3. 계속되면 PC를 다시 시작합니다.
4. 그래도 안 되면 설정 → 앱 → 설치된 앱에서 `ezPDFReader 2.0G`를 제거합니다. 이 PC의 앱 목록에는 WebCube 항목이 따로 없으며, 뷰어를 제거해도 `TUCtlSystem` 서비스가 남을 수 있습니다(위 명령으로 확인).

- 정부24 전자문서를 다시 열면 같은 일이 반복됩니다.
- 보호된 문서 화면이 캡처되지 않는 것은 그 기관이 의도한 동작입니다.

같은 안내가 앱 안내 창, `installer/docs/사용법.txt` 8절, `README.md` 문제 해결에 있습니다.

## 8. 핀캡처 변경 (0.6.1)

| 변경 | 내용 |
|---|---|
| 감지 함수 | `is_pure_black(img)`: 이미지 전체가 `#000000`인지 Qt의 C++ 이미지 비교로 판단(2560x1440도 수 ms). `screens_capture_blocked(grabs)`: 모든 모니터가 완전 검정일 때만 `True` |
| 영역 지정·핀 | `RegionCaptureSession.start()`가 오버레이를 띄우기 **전에** 검사. 차단이면 검은 오버레이를 띄우지 않고 `blocked` 신호 |
| 전체 화면 | 커서가 있는 모니터가 검정일 때만 나머지 모니터까지 확인 |
| 창 캡처 | 창 이미지가 검정이고 모든 모니터도 검정일 때만 차단으로 판단. 실제로 검은 창은 정상 캡처 |
| 차단 시 동작 | 저장·클립보드 복사·보관함 기록 안 함. 트레이 알림 + 항상 위에 뜨는 비모달 안내 창 "화면 캡처가 막혀 있어요"(단축키를 막지 않음). 로그에 `[capture]` 한 줄 |
| 테스트 | `tests/test_capture_blocked.py` 9개: 감지 함수, 영역·핀·전체·창 흐름, 진짜 검은 창, 안내 창 문구, 정상 캡처 무영향 |
| 문서 | `사용법.txt` 8절에 증상과 해결 순서 추가 |

**차단을 우회하지 않습니다.** DXGI Desktop Duplication, Windows.Graphics.Capture로 바꿔 찍기, 주입된 후킹 해제(unhooking) 같은 코드는 넣지 않습니다. 이유는 다음과 같습니다.

- 문서를 보호하려는 기관의 의도를 존중합니다.
- 보안 프로그램과 다투는 코드는 백신 오탐과 충돌 위험을 키웁니다.
- 핀캡처가 할 일은 "왜 검은지"를 알려 주는 데까지입니다.

이 원칙은 운영 규칙(`AGENTS.md`)의 불변 조건입니다.

## 9. 남은 과제

| # | 과제 | 내용 |
|---|---|---|
| 1 | 한 모니터만 막는 차단 | 지금은 **모든** 모니터가 완전 검정일 때만 감지합니다. 보호 창이 있는 모니터만 검게 만드는 제품이면 감지하지 못하고 검은 이미지가 저장됩니다. 반대로 모니터가 하나뿐인 PC에서 화면 전체가 실제로 검은 경우(작업 표시줄이 숨겨진 전체 화면 검은 영상 등)에는 안내 창이 잘못 뜰 수 있습니다. |
| 2 | 로고·문구형 차단 | 검정 대신 로고, 경고 문구, 다른 단색으로 바꾸는 제품은 감지하지 못합니다. 감지 범위를 넓히면 오탐 위험이 커지므로 실제 사례를 모은 뒤 정합니다. |
| 3 | 정착 테스트: 뷰어가 앞에 있을 때만 막히는가 | 아직 확인하지 않았습니다. 아래 상황마다 핀캡처와 Windows 캡처 도구로 찍어 결과와 정상으로 돌아오기까지 걸린 시간을 기록합니다. 뷰어가 맨 앞 / 뷰어가 열려 있으나 뒤에 있음 / 뷰어 닫음·브라우저 열림 / 둘 다 닫음 / 재부팅 직후 / `ezPDFReader 2.0G` 제거 후. 실제 보안 프로그램이 있어야 하고 pynput은 프로그램이 보낸 키 입력을 무시하므로 자동화할 수 없으며, 손으로 시험합니다. 결과에 따라 안내 순서와 문구를 고칩니다. |
| 4 | WebCube 잔존 여부·제거 방법 | 뷰어 제거 뒤 `TUCtlSystem`이 남는지 확인합니다. 지금 안내 창과 `사용법.txt`는 "WebCube 제거"를 권하지만, 이 PC의 설치된 앱 목록에는 해당 항목이 없습니다. 실제로 가능한 방법으로 문구를 고쳐야 합니다. |
| 5 | 감지 로그에 시각 기록 | `[capture]` 줄에 시각이 없어서 이번 기록의 감지 시각을 실행 시작 줄로 추정했습니다. 감지 줄에 시각을 넣으면 다음 사건 분석이 쉬워집니다. |
